# 端末をまたいだ作業の続け方

同じPart ScoutのURLを、同じChatGPT利用者でiPhoneとPCから開きます。入力はまず端末に保存され、接続できると利用者専用の保存先へ同期されます。画面の「同期済み」と日時を確認してから端末を移ると、続きから作業しやすくなります。

同期するのは、本体の設定・原価・作業位置、送料計算画面の入力、品番別の調査リストです。初めて別の端末で開いたときは、空の初期値で保存先を上書きしません。通信断の間に行った編集は端末に残り、再接続・画面復帰・手動同期で送信します。

同じブラウザの古いタブが別タブの編集を上書きしようとした場合も、両方をバックアップして再読み込みする案内を表示します。

別の端末と違う編集をした場合は、自動で片方を捨てず競合を表示します。バックアップを保存し、採用する編集を選んでください。選ばなかった版も復旧用に保持します。保存容量が足りない場合は、保存成功と表示したり、必要な復旧コピーを省いて上書きしたりしません。端末の保存領域を本人が削除した場合や端末を紛失した場合、まだ同期されていない編集までは戻せません。

調査リストにメーカーと品番を登録し、「未調査・調査中・要確認・完了」の進捗とメモを残します。品番の見積を再開し、別の品番へ移るときは元の見積を残します。リストへの追加・再開は外部サイトへの自動アクセスを開始しません。部品情報の取得は見積画面の操作で行い、既存の1分1件・1日30件等の制限を維持します。

Work用の引き継ぎ文はコピーして利用します。これはPCへの接続やeBay/CPaSSのログインを代行する機能ではありません。実際のブラウザ操作には接続された環境と権限が必要です。出品・購入・支払い・発送依頼などの実行は今回追加していません。現物の計量・梱包・受け渡しも人が行います。

## 構成と運用

- 新しい有料API・外部サービス契約を追加せず、既存SitesのD1保存先を使用します。取引費用やプラットフォーム自身の利用条件は別です。
- GitHub Pagesなど保存APIのない静的ホストでは端末保存で利用でき、画面に同期できないことを表示します。端末間同期はSitesのURLで利用します。
- GET/PUT `/api/workspace/main`、`shipping`、`queue`。利用者はSitesが認証して転送する `oai-authenticated-user-id` から決定し、ブラウザ指定の所有者IDは受け取りません。ハッシュ化した利用者キーと文書種別でデータを分離します。
- PUTは同一OriginのJSONのみ、要求全体2,000,000バイトまで。GETで得た利用者キーをPUTの前提条件として再照合し、通信の途中でログインが変わった場合も前の編集を送りません。保存版番号による単一SQLの比較更新を行い、古い版の更新は409です。未認証401、保存先障害503。応答はprivate/no-storeで、サービスワーカーにも保存しません。
- サーバーのSQL移行は0001を追加し、適用済み0000は変更しません。既存localStorageキーとバックアップ形式は維持します。キー、注文者情報、OAuthトークン等をGitHubに入れません。
- 本体、単独見積、調査リストは独立した文書です。金額計算・関税確認・有効期限・仕入判定は既存の検証を通った処理を使い、同期が確認手続きを代行することはありません。

## 検証範囲

実装時の検証は、2台の独立した保存領域と実SQLite/構築済みWorker間の同期、同時編集、書き込み後の応答喪失、アカウント分離、通信断からの再開、画面入力・復元・品番切替を対象とします。実iPhone/PCのブラウザ同士での操作、実eBay/CPaSS接続は別途の実機確認です。
