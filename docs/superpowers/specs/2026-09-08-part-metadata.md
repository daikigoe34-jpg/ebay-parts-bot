# 品番から送料を出す

ユーザー承認: 「やれ！アマヤマじゃなくても、寸法と重量データどこからでも拾え！送料はめちゃくちゃ聞いてくるから重要じゃ」。先行する送料計算・保存・同じURLへの公開の承認を引き継ぐ。

## 結果

メーカーと品番から公開の商品仕様を読み、商品重量・三辺・出典・取得日を保存する。参考箱と緩衝材を加え、既存の SpeedPAK Economy 米国48州の参考送料を計算する。商品カードと単独送料画面の両方から使える。入力は即時保存し、同じ品番・同じ梱包条件の実測を次回に使う。追加の有料API契約、AI推測、ログイン情報は不要。

## 境界

- 商品寸法は発送箱の外寸ではない。小売店の Item Dimensions / Item Weight は単品・包装の範囲が保証されない掲載値と表示する。商品情報だけで送料確定・仕入可にはしない。
- 品番の完全一致を製品仕様の Manufacturer Part Number / SKU で確認する。関連商品・互換品・後継品・検索一覧・写真・車体寸法は採用しない。
- 不明は不明。欠測や複数の異なる掲載値は自動採用しない。ゼロ、平均、安い方で埋めない。403・429・robots拒否は回避しない。
- 既存の料率表、通関費の区別、確認失効、手入力送料、バックアップと保存キーを維持する。米国48州以外は現在の計算対象外。
- 同じ Site / 同じ origin を更新する。既存の本人限定アクセスを維持する。Sites操作とそのソース編集は親エージェントのみ。

## 構成

元のGitHubリポジトリに公開ページ取得の純粋ESMモジュール、箱計算と保存のブラウザモジュール、共有の入力UIを置く。Siteは既存静的資産を保持した軽量Workerに変更し、同一originの GET /api/part-metadata だけを追加する。外部サイトのCORSに依存しない。実行時は標準fetchのみで有料サービスを呼ばない。GitHub Pages単体では取得APIは動かないことを明示する。

## 実際に確認した取得元（2026-09-08）

公開robotsは /online/ と /onlineapi/ 等を拒否し、下記製品URLのパスは許可している。通常のHTTP GETで200と同じホストへの正規URL転送を確認済み。

|HONDA|https://www.hondapartsnow.com/genuine/honda~15400-plm-a02.html|15400-PLM-A02: 7.3 x 7.2 x 5.2 inches / 0.50 Pounds|

## 参考箱

すべて BoxBank のメーカー掲載値を2026-09-08に確認。所有・購入済みとは扱わない。箱の製造公差と緩衝材の実際の配置は実測で確認する。

|ID|外寸cm|内寸cm|箱重量g|出典|
|---|---|---|---|---|
|cb11-060|25,18,16.3|24,17,14.8|145|https://www.boxbank.jp/c/cardboard/cb11-060|
|cb09-080-a4|31.5,22.5,25|30.5,21.5,23|264|https://www.boxbank.jp/c/cardboard/cb09-080-a4|
|cb03-100-a4|34,25,25.5|33,24,24|344|https://www.boxbank.jp/c/cardboard/cb03-100-a4|

既定の参考条件は商品1個、各面の緩衝材1cm、商品1個当たり緩衝材50g。仮定と明記し変更可能にする。6方向の直方体の配置で内寸に収まる箱を選び、送料には外寸を使う。単独送料画面の個数は1〜20個の同じ品番のみ。商品カードは既存の1個単位の利益計算に合わせて1個に固定する。総重量 = 個数×(掲載商品重量+緩衝材重量)+箱重量。既存の課金重量切上げに渡すため、中間重量を切り捨てない。入る箱がない場合は手動の実測へ案内する。

## 受入れ条件

1. 対応品番を入力して1回取得すると掲載値・取得元リンク・取得日・箱の仮定・参考送料が表示される。
2. 0.80 lb = 0.362873896 kg、3.1 inch = 7.874 cm。上記Toyota + cb11 + 50g = 0.557873896 kg、箱体積7335cm³、課金重量0.917kg、1kg料金となる。
3. 初回の梱包後実測を明示操作で保存でき、同じメーカー・品番・個数・梱包設定で再利用できる。通常の参考値を実測として自動保存しない。
4. オフライン・画面を閉じる・バックアップ復元でも既存の値と新しい作業を失わない。保存不能は画面に明示する。バックアップは旧形式も読める。
5. 違う品番への遷移、取得中の手入力変更、古い応答、数量変更で誤った寸法を適用しない。出典・梱包の変更は仕入・関税の確認を失効させる。
6. 上限・単位不明・表の矛盾・別品番転送・任意URL・robots拒否・巨大応答は安全に未取得となる。APIエラーやHTMLログイン画面を値として保存しない。
7. 元の送料・利益・入力保存テストを保持し、新しい境界の実行テストを追加する。元リポジトリのPRでCIを通し、同じSiteを公開してNotionに実装範囲と残る制約を記録する。
