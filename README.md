# Part Scout Mobile v0.4.1

**eBay Production Browse APIだけで、日本車純正部品を自動探索し、iPhoneで仕入候補を上から処理するPWA**です。

GitHub Actionsが毎日、検索語のローテーション、純正品番抽出、同一品番の競合・出品相場調査、販売増分の継続観測、為替、国内仕入候補、手数料、関税一次概算、利益判定まで実行します。

## 重要な前提

- 使用するeBay認証情報はProduction App IDとProduction Cert IDです。
- Productionキーを持っていても、Buy/Browse APIのProduction利用権限が別途必要な場合があります。
- 標準のBrowse APIは、過去90日の成約履歴を直接返しません。
- 本アプリは`estimatedSoldQuantity`を毎日保存し、**観測開始後に確認できた累計最高値の増分だけ**で販売ペースを学習します。欠測を0へ変換しません。
- 出品に表示される過去の累計販売数は参考表示に残しても、仕入判定には使いません。
- 有料API、生成AI API、OCR、スクレイピング基盤は使用しません。

公式要件：

- https://developer.ebay.com/api-docs/buy/static/buy-requirements.html
- https://developer.ebay.com/api-docs/buy/browse/overview.html

## v0.4.1で直したこと

- 入力直後に端末へ保存し、別サイトへ移動しても設定・金額・作業位置を復元
- 保存失敗を画面へ表示し、JSONバックアップの保存・復元を追加
- 通信切断・HTTPエラー時は最後の正常な調査結果を表示し、更新待ちの間は購入候補にしない
- アプリ更新時も旧版の調査キャッシュを引き継ぐ
- 販売数の欠測・累計リセットによる過大計上と、非USD価格の誤集計を修正
- 空欄・不正な金額、未確認の手数料、古い為替では購入候補にしない

- International Feeの割引は適用確認後のみ。関税実見積は概算へ上乗せせず置換

## 自動化範囲

| 処理 | 状態 | 内容 |
|---|---|---|
| Production OAuth診断 | 自動 | App IDとCert IDの組み合わせを確認 |
| Browse API権限診断 | 自動 | OAuth成功後、検索APIを1回実行して権限を判定 |
| eBay候補探索 | 自動 | 日本車メーカー、純正語、小型部品語を順番に巡回 |
| 純正品番抽出 | 自動 | Item Specifics優先、タイトルを補助利用 |
| 同一品番市場調査 | 自動 | 競合数、セラー数、出品価格中央値、価格帯を集計 |
| 販売ペース | 自動学習 | 日次の`estimatedSoldQuantity`増分だけを記録 |
| 終了・売切れ出品 | 自動 | 観測履歴に残し、確認済みの増分を失わない |
| 為替 | 自動 | ECB公開レートからUSD/JPYを更新 |
| 楽天価格 | 任意自動 | 楽天公式APIキー登録時に品番一致を取得 |
| モノタロウ | 1タップ | 品番入力済み検索を開く |
| 国際送料 | 自動概算 | 商品名から小型プロファイルを選択。最終確認は必要 |
| eBay手数料 | 自動 | プラン、カテゴリ、売上総額、海外決済料等を計算 |
| Payoneer | 自動概算 | 出金率、固定費、年間費用配賦を別計算 |
| 米国関税 | 一次概算 | 原産国別の保守値。HTSUS・DDP実見積は最終候補のみ確認 |
| 利益判定 | 自動 | 販売下限、競合、利益、利益率、確認状態を総合判定 |

## 初回設定

### 1. eBay Productionキーを登録

GitHubリポジトリで次を開きます。

`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| Secret名 | 入れる値 |
|---|---|
| `EBAY_CLIENT_ID` | Production App ID / Client ID |
| `EBAY_CLIENT_SECRET` | Production Cert ID / Client Secret |

キーはJavaScript、README、Issue、チャットへ貼らないでください。

### 2. GitHub Pagesを有効化

`Settings` → `Pages` → `Build and deployment` → `Source: GitHub Actions`

### 3. 初回調査を実行

`Actions` → `eBay自動リサーチ` → `Run workflow`

検索語は空欄で構いません。

実行後、`web/data/setup_status.json`に次のいずれかが保存されます。

| 状態 | 意味 | 次の操作 |
|---|---|---|
| `ready` | OAuth・Browseとも成功 | 操作不要 |
| `missing_secrets` | キー未登録 | 2つのSecretを登録 |
| `auth_failed` | キーの組合せ不正 | Secretを修正 |
| `browse_access_denied` | キーは認証できたがBrowse本番権限なし | eBayのBuy API Production要件を確認 |
| `rate_limited` | eBay側のAPI上限 | 次回実行を待つ |
| `ready_partial` | アプリの安全上限で分割停止 | 操作不要。次回続行 |
| `temporary_error` | 一時障害 | ワークフローを再実行 |

### 4. iPhoneへ追加

1. GitHub Pagesの公開URLをSafariで開く
2. 共有ボタンを押す
3. `ホーム画面に追加`を選択
4. ホーム画面の`Part Scout`を開く

## 日常操作

### 観測が育つまで

`今日やる`に「自動観測中」と出ている間は操作不要です。

### 高信頼候補が出た後

1. `今日やる`の最上部に表示された1件を開く
2. 楽天またはモノタロウで価格・在庫・国内送料を確認
3. 必要な金額だけ修正
4. 仕入条件確認済みにチェック
5. 原産国・10桁HTSUS・DDP関税実見積額を入力
6. 関税確認済みにチェック
7. `購入候補`になった商品だけ仕入判断

人が調べる対象は、高信頼かつ市場基準を通過した最終候補だけです。

仕入価格・送料・関税の確認は7日間有効です。期限切れや対象金額の変更時は再確認します。売価を手入力しなければ、次回調査の出品価格中央値を自動で反映します。

### 通勤中の中断・再開

入力は即時保存されます。画面上部の「端末に保存済み」を確認して閉じ、同じ端末・同じブラウザで開き直してください。正常な調査結果を一度取得した後は、圏外でも保存済み結果と入力を表示できます。通信復帰時に最新データへ更新します。初回起動には通信が必要です。

「設定 → バックアップ」で入力・設定・作業位置をJSONへ保存できます。端末移行やブラウザデータの削除前に保存し、移行先で「復元」してください。バックアップにAPIキーや調査結果は含めません。Safariとホーム画面アプリは保存領域が分かれる場合があるため、日常はホーム画面アプリに統一します。

端末の保存領域をOSや本人が消去した場合まで自動復元は保証できません。保存領域不足などで書き込めなければ赤いエラーを表示します。

## 販売ペースのロジック

### 初回観測

初回に確認できた累計販売数は基準値として保存します。初回以前の販売を90日実績へ加えません。

### 2回目以降

```text
観測販売数 = max(0, 今回確認できた累計販売数 - 観測中の累計最高値)
```

欠測は不明として除外します。数量が減ってから元に戻るだけでは販売を加算しません。実際に累計がリセットされた場合は過少計上になる可能性があります。この推定を過去90日の実成約数とは表示しません。

出品ごとに観測期間が異なるため、各出品を個別に換算して合算します。

```text
出品ごとの90日ペース = 観測期間中の正の増分 ÷ 観測日数 × 90
品番全体の90日ペース = 同一品番の各出品ペースの合計
```

### 仕入判定に使う数値

表示用の点推定ではなく、Poissonモデルによる保守的な信頼区間下限を使います。

- 観測7日未満：判定値0
- 7～13日：低信頼
- 14～29日：中信頼
- 30日以上＋競合精度・市場カバー・追跡数を満たす：高信頼

累計販売数が250個と表示されていても、アプリ観測後の増分が0なら、仕入判定の販売数は0です。

## 競合数

品番検索の総件数には類似品番や適合説明が混ざるため、そのまま競合数にしません。

```text
推定競合数 = 検索総件数 × 返却サンプル内の完全品番一致率
```

実際に詳細確認できた一致件数より小さくならないよう補正し、精度を`高／中／低／不明`で表示します。

## 手数料・関税

利益計算は次を分離しています。

- eBay Final Value Fee
- 注文固定料
- International Fee
- Promoted Listings
- 出品料
- 追加Final Value Fee
- eBay手数料に対する日本の消費税
- Payoneer出金率・固定費・年間費用配賦
- 返品・不良引当
- 仕入、国内送料、国際送料、梱包費
- 関税一次概算、通関固定費

料金や関税は変更されるため設定可能です。関税はスクリーニング用であり、確定値ではありません。

初回に自分のeBay・Payoneer手数料設定を確認してください。売上額だけで海外決済料の割引適用は推測しません。自動為替が7日より古い場合や予備値の場合、購入候補判定を止めます。必要なら確認した為替を手入力できます。

[2026-09-08の米国関税確認](docs/TARIFF_REVIEW_2026-09-08.md)：日本の対象自動車部品の232条、新しい強制労働301条、旧関税の終了、少額免税停止を区別しています。国別の試算率は実税率の上限ではなく、現在の実見積を優先します。

## 品番からの参考送料

`web/shipping-calculator.html` と商品カードの「品番から送料を出す」は、同じ寸法・梱包ロジックを使用します。TOYOTA、NISSAN、HONDA、SUBARUの公開販売店ページの品番一致表から、重量・寸法だけを取得します。販売店の仕様は裸の部品／梱包済みの区別が未確認で、他店照合済みや実測済みを意味しません。取得元・取得日・原表記を表示し、不足・矛盾・拒否時には箱を自動決定しません。

箱はBoxBankの3種類の内寸で収まりを確認し、外寸・箱重量・緩衝材重量を既存のSpeedPAK参考計算へ渡します。専用送料画面では数量・外周の余裕・緩衝材・箱を変更でき、申告額には荷物全体の商品合計を入力します。商品カードは既存の1個分の販売・仕入モデルを保つため数量1に固定し、複数個の利益を推測しません。梱包後に実測して保存ボタンを押した記録だけを実測として扱い、メーカー・品番・数量・梱包設定が一致した場合だけ再利用します。入力と検証済み取得情報は端末に即時保存し、従来のバックアップも復元できます。

同一オリジンの `GET /api/part-metadata?make=TOYOTA&part=90915-10001` を `server/part-metadata.mjs` の `handlePartMetadata(request)` に接続してください。静的なGitHub Pages単体にはこのAPIがありません。APIが利用できない場合も手入力・保存済み情報による計算は使えます。サーバーモジュールにランタイム依存はありません。外部通信は4販売店のHTTPS製品ページとrobots.txtだけに限定し、最大3回の同一ホストリダイレクト、1取得20秒・全体45秒、robots64KB・HTML1MBの上限を設けています。403等を回避する再試行はしません。

成功キャッシュは7日・最大200件、失敗は5分、robotsは6時間・最大4ホストです。成功・部分取得の再確認でも取得後24時間は保存値と元の取得日を返します。同じ品番の進行中リクエストと、同じホストの進行中robots取得を共有します。ブラウザも成功・部分取得は7日、失敗は5分で再利用を判断し、取得情報・実測記録を各200件に制限します。取得日の表示と明示的な再確認を用意し、自動の再試行・巡回は行いません。最終送料・仕入条件・関税の確認は従来どおり別途必要です。

公開環境では、このモジュールの前段に永続的な取得制限・キャッシュを接続してください。画面が案内する上限は全メーカー共通で新規取得1分に1回・日本時間で1日30回です。保存済みデータ・実測荷物の再利用は回数に含みません。モジュール内のメモリキャッシュだけでは環境をまたぐ制限を保証しません。拒否応答の `retryAfterSeconds` はHTTPのRetry-After（秒またはHTTP日付）から得た任意の正の有限数で、robotsの429も元の理由とともに返します。前段のゲートは403・robots拒否を確認待ち、429を最低24時間かつRetry-After以上停止し、過大な値は確認待ちとして扱ってください。ゲート理由 `acquisition_cooldown`・`daily_lookup_limit`・`provider_paused`・`source_policy_review`・`storage_unavailable` は通常のschemaVersion1応答で表示でき、一時的な取得間隔・日次上限・保存障害は販売店の取得結果として保存しません。
